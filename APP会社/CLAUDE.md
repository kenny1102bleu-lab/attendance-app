## 【最重要原則：指示書・ルールの毎度必読＆実装完了まで路線厳守】

- **🔥 【絶対厳守ルール】開発開始前および毎回のタスク実行時に、必ずプロジェクト内のすべての指示書（`.md`ファイル）とルール（指示書やCLAUDE.md）を最初から最後まで精読し、そこに書かれている要件（トレンド収集、全自動化要件など）を絶対に漏らさず実装すること！同じ指摘を二度と社長にさせないこと！**
- **📚 【ナレッジ必須参照ルール】オブシディアンのナレッジまとめ（Obsidian / Projects / Knowledge 等）には、これまでこのAPPや業務全体で必要として収集・蓄積されたあらゆる重要情報がまとまっています。各エージェント（役割ごとのAIや開発プロセス）は、いかなる行動やコード作成を行う前にも、必ずこれらのナレッジ・過去ログを最初から最後まで精読し、前提と脈絡を完全に把握した上で行動すること！**
- **🎯 【内部構築完了までの絶対ルール】システムの内部構築（完全自動化の統合完了）がすべて完了するまで、新しいコード作成や修正にあたっては、必ずObsidianの実装プロセス（Projects/ フォルダ等）内のファイルを最初から最後までしっかりと読み直した上で作業を行うこと！**
- **🛡️ 【エックス新アルゴ（Grok 2026）破壊コードの絶対禁止】** SNS自動投稿コードを編集する際、「アフィリンク等の外部リンク直貼り」「投稿後の放置（30分以内未返信）」「1日4回以上の多頻度量産」を行うコードの記述を永久に禁止する。必ずリプ欄・自動DM誘導および自動30分以内リプライ交流ロジックを遵守すること。
- **⚠️ 【日本語マルチバイト文字数ガードの死守】** XなどのSNS自動投稿文字数切り出しロジックは、単純な文字数ではなく、必ず実装済みの日本語マルチバイト対応（全角=2単位、半角=1単位）関数（`sliceTwitterText`）を適用し、文字数制限超過によるX APIエラー（400エラー）を永久に回避すること。
- **⚡ 【GASデプロイミス防止・コード変更範囲の極小化】** GASコードを修正する際、無関係なインデント調整や余分なリファクタリングを避け、変更箇所を1ヶ所に固める（contiguous）ことで、ユーザーの手動デプロイ（コピペ）における貼り付けミスや差分確認の摩擦を極限まで減らすこと。
- **🔍 【勝手な仕様捏造の禁止（設定値・フォルダIDの優先検索）】** 設定値、スプレッドシート構成、GoogleドライブのフォルダIDなどをコード内にハードコーディングすることを禁止する。必ず `getKCSSettings()` やスプレッドシートの実構成、またはObsidianのナレッジを検索・確認してロジックに組み込むこと。
- **❌ 新しいアイデアを勝手に追加しない / 別のツールを試さない / 路線を変更しない**
- **✅ 今決まった構成を完成させる / 実装→テスト→稼働の順番を守る**
- **✅ 完全稼働後に初めて改善を検討 / 迷ったら「今の路線に戻る」**

## システム全体アーキテクチャ（Make.com × n8n ハイブリッド）

```
【CEO（あなた）】スマホから Discord で指示
         ↓
【Discord】指示系統（#KCS本部, #knowledge 等）・ログ表示
         ↓
【Make.com】Discord監視（無料2シナリオ・ポーリング）
  Scenario 1: テキスト / !コマンド / HAL: / すなくん: → GAS
  Scenario 2: #knowledge 画像添付 → GAS（Gemini Vision）
         ↓                    ↓
【n8n 無料（2本）】     【GAS（全ロジック処理）】
  朝礼9時 → GAS          コマンド解析・AI生成・Discord返信
  日次20時 → GAS
         ↓
【Claude / Gemini API】AI処理（文章生成・画像解析・分析）
         ↓
【各 SNS / 外部出力】X, YouTube, AITuber OnAir, ライブ配信
         ↓
【GitHub / Obsidian】全ログ自動同期・ナレッジ蓄積
         ↓
【NEXUS CO.（Webダッシュボード）】リアルタイム進捗・管理
```

## Obsidian ナレッジ管理 (KCS-Vault)

- **概要**: これまでこのAPPやプロジェクト開発に必要な、インターネットや実地から拾い上げてきたあらゆる重要情報を網羅的にまとめたナレッジベースです。**各エージェント（役割ごとのAIや開発プロセス）は、行動やコード書き換えを行う前に、必ずこのナレッジ（`/Knowledge/` や `/Projects/` 以下の各種ログファイル）をすべて読み込み、前提知識としてフルに活かして行動しなければなりません。**
- **リポジトリ**: `KCS-Vault` (Private)
- **同期**: n8n から GitHub API 経由で Push
- **フォルダ構成**:
  - `/Daily/`: 朝礼・日次ログ
  - `/Projects/`: HAL / Affiliate / CoverSong / DogYouTube / HP / EC
  - `/Knowledge/`: 推し活 / ファッション / 美容 / SNSバズ / グルメ
  - `/Strategy/`: 設計・ルール・トレンド情報
  - `/Rules/`: キャラ設定・アクションルール

## やってはいけないこと

- **イシューの勝手な変更**: 進行中のタスクから逸脱した提案や変更。
- **原則を無視した新機能の提案（実装完了まで）**
- `bridge.config.json` のGAS URL直接編集（`store.js` 経由で利用）
- `App.jsx` への過度なビジネスロジック追記（`store.js` や `views/` に分離）
- Gemini APIへの非文字列オブジェクト送信（必ず `toText()` を通す）
